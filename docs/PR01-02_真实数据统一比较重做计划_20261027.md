# PR01-02 真实数据统一比较重做计划

2026-10-27。用户确认以 MEME/STREME 已使用的真实启动子数据及既有划分为基础，Embedding 等方法对齐该数据；统一采用适合课程实践的较宽松候选展示和片段评价。CNN 路线尚未收尾，暂不强行加入比较，收尾后须使用相同数据、对照及评价口径。

## 数据和现状

- 第一阶段使用 `data/processed/pr01_02_data_v2/` 下 TJU 六物种既有 Discovery、Development、天然负类及配对 dinucleotide shuffle；核对序列 ID、样本数量、划分和哈希，不重新划分或以新合成数据替代。
- 已有六物种 ProkBERT 和 One-hot 候选及运行记录，先审计可复用范围，缺项才补跑。冻结模型和既有产物不覆盖。
- `results/motif/m3_expanded_20261009/cases.tsv` 记录 54 组运行；当前核对 12 个 STREME 原生输出目录存在、42 个扩展路径不存在，其中包括 MEME。先查找备份与 PWM；不能恢复时在可用 MEME Suite 环境按原数据和记录的参数补跑，并标明新运行来源。不要用汇总数字冒充完整 PWM。
- RegulonDB 和 DBTBS 的整体/σ 分组在六物种主流程跑通后扩展；DBTBS 与 TJU 存在重叠，不作为独立外部统计验证。

## 执行顺序

1. 数据审计：建立每物种数据划分、背景、候选 PWM 和来源清单；检查原始序列、模型和候选哈希，列出可复用与缺失项。
2. 传统候选恢复：提取可用 STREME PWM，核实 MEME 和扩展结果；恢复缺失产物或以原有数据、条件和记录参数补跑。记录工具版本、失败和数据来源。
3. 单物种端到端：优先 B. subtilis，使 MEME、STREME、One-hot 和 BERT 使用同一输入、候选格式及扫描；不只使用 STREME 已筛主候选与其他方法完整候选相比较。
4. 冻结共同评价：各方法使用同一背景、双向扫描、候选预算和排序原则；采用可适用于不同 PWM 宽度的局部重叠及偏移规则。阈值先在 Discovery 确定并记录；完整候选和等数量候选两个视图并列，天然对照与 Shuffle 分开。
5. 扩展至六物种：报告正类与对照命中、片段相似、匹配长度、位置和真实 Logo；保留低值和缺失，不编造数据或把参考相似称作已验证功能。此前已观察的 Development 如实标作探索；不把此前使用过的 Holdout 称为全新验证。
6. CNN 收尾：保留其既有实验、失败和结论；后续确定收尾方案，完成后按同一真实数据、对照、候选预算和评价接入，并注明 CNN 的标签监督条件。
7. 核验交付：检查相同数据及参数、候选和报告图表来源，记录缺失和局限，更新项目文档并同步 GitHub。
