# 项目章程与开发路线

## 1. 项目成功标准

项目不以某一个固定分数作为唯一目标，而以“问题定义清楚、数据来源可追溯、实验链闭合、结论有证据、代码可复现、协作可检查”为成功标准。

最终至少应达到以下结果：

- 覆盖多个物种，并按 sigma 因子类型建立可审计的分组；
- 有完整的全体 motif、分组 motif、FIMO 定位、间距/排列和跨数据集验证结果；
- 对已知元件和 de novo motif 做定量比较，而不是只展示 sequence logo；
- 用随机/打乱背景、重复种子或重复数据抽样检验发现结果是否稳定；
- 对 RQ1-RQ3 给出明确、有限度、可由图表复核的结论；
- 完成课程必做实验，并完成“强度关联”和“组合模式”两项扩展；
- 每个结果都能追溯到输入数据版本、配置、命令、代码提交和输出文件。

## 2. 技术路线

~~~text
公开数据与元数据
        ↓
启动子序列标准化、去重、分组、背景构造
        ↓
M2 EDA：长度、GC、已知元件位置和保守度
        ↓
M3 motif 发现：MEME + DREME/STREME，全体与分组
        ↓
FIMO 定位 + 已知元件重合 + motif 相似性
        ↓
M4 间距/排列 + 跨物种/跨数据集一致性
        ├── 扩展 1：motif 与启动子强度关联
        └── 扩展 2：motif 组合共现与网络
        ↓
M5 报告、可视化、答辩材料和可复现仓库
~~~

## 3. 基线与对照体系

### 3.1 代码基线

仓库通过 baselines/memesuite-lite 锁定了一个轻量 Python motif 处理基线，当前固定到 Git 子模块提交 251bf9a2f83de3342c45d062806cd681dd937790。它提供 MEME 格式读写、FIMO 和 Tomtom 相关能力，便于将 motif 定位、比较和统计封装为可测试代码。

### 3.2 公开候选项目比较

以下星标数量是 2026-09-05 检索 GitHub 公开页面时看到的数量，会随时间变化；星标只作为初筛信号，最终按任务匹配度、可复现性、许可证和维护状态判断。

| 项目 | 公开星标 | 与本项目的关系 | 决策 |
| --- | ---: | --- | --- |
| [memesuite-lite](https://github.com/jmschrei/memesuite-lite) | 36 | Python 轻量实现，提供 FIMO/Tomtom 等 motif 处理和测试，MIT 许可证 | 作为代码基线，以 Git 子模块锁定 |
| [ANNOgesic](https://github.com/Sung-Huan/ANNOgesic) | 34 | 面向细菌/古菌注释，包含基于 TSS 的 promoter motif 发现，使用 MEME/GLAM2 | 作为流程和输出组织参考，不直接纳入全部平台功能 |
| [memes](https://github.com/snystrom/memes) | 未在当前页面稳定显示 | R 接口，封装 MEME Suite 的 motif 发现、FIMO、Tomtom 等工具 | 作为后续 R 生态对照候选 |
| [memeMotifs](https://github.com/BioinfGuru/memeMotifs) | 6 | MEME Suite 工作流教程，覆盖 MEME、DREME、Tomtom、SpaMo、FIMO | 作为参数和分析步骤参考 |

选择 memesuite-lite 的原因是：它能直接作为 Python 侧的可测试处理层接入本项目，体量和依赖适合课程协作；它不包含完整的 MEME/DREME/STREME 发现程序，所以正式 motif 发现仍使用 MEME Suite 命令行工具，并在运行说明中锁定版本。这一边界必须在报告中写清楚。

### 3.3 实验基线

| 编号 | 基线/对照 | 用途 |
| --- | --- | --- |
| B0 | -10/-35 box 共识/PWM 扫描 | 验证已知核心元件和位置基准 |
| B1 | 全体序列 MEME | 观察不分组时的总体 motif |
| B2 | 全体序列 DREME/STREME | 观察短 motif 和大样本富集结果 |
| B3 | 按 sigma 类型分组发现 | 直接回答类型差异问题 |
| B4 | 按物种/数据集分组发现 | 支撑跨来源一致性分析 |
| N0 | 保持长度与碱基组成的随机/打乱序列 | 检查统计显著性和假阳性 |

MEME Suite 命令行工具作为 motif 发现的标准运行环境；memesuite-lite 作为 Python 侧的可复现处理与验证组件。外部工具版本、参数和运行方式在环境准备完成后写入 docs/运行说明.md。

## 4. Benchmark 与大众评测方式

本项目采用“多指标、分层验证”而不是只报告一个 motif 数量。主指标如下：

| 维度 | 指标 | 解释 |
| --- | --- | --- |
| 已知元件恢复 | motif-PWM 相似性、已知位点重合率、precision/recall/F1 | de novo 结果是否能恢复已有生物学知识 |
| 统计显著性 | motif E-value、FIMO p-value/q-value、背景对照差异 | 结果是否可能由随机序列造成 |
| 位置规律 | 元件相对 TSS 的位置分布、间距中位数/IQR、KS/Wasserstein 等分布差异 | 是否存在稳定的空间组织 |
| 类型差异 | 分组 motif 组成差异、效应量、校正后显著性 | sigma 类型是否有特异模式 |
| 跨来源稳定性 | motif 相似性、出现率差异、排序相关、Jaccard/聚类一致性 | 模式是通用还是数据集特异 |
| 随机稳定性 | 多随机种子/重采样下的发现率和置信区间 | 结果对抽样是否敏感 |
| 组合模式 | 共现 lift、互信息/显著性、网络边稳定性 | motif 是否形成可重复组合 |
| 强度关联 | Spearman 相关、效应量、分组差异和多重校正 | motif 是否与启动子强度相关 |

评测协议：

1. 发现数据与验证数据按物种或数据集隔离，避免把同源序列同时放入发现和验证集合。
2. 所有组比较使用同一序列窗口、同一背景构造和记录完整的参数。
3. 至少设置一个保持长度和碱基组成的负对照；必要时增加 dinucleotide-preserving shuffle。
4. 每个关键实验记录随机种子、输入文件哈希、软件版本和完整命令。
5. 对多 motif、多位置、多组比较使用明确的多重检验校正，并在报告中区分探索性结果和验证性结果。
6. 结果表同时报告样本数、阈值、效应量和不确定性，避免只展示最优结果。

## 5. 分阶段开发流程

### M1：问题分析和数据审计

- 确认数据源、许可证/使用条件和可下载方式；
- 确定物种、sigma 类型、TSS/启动子坐标和强度标签字段；
- 建立统一 FASTA header 和 metadata schema；
- 设计去重、质量过滤和分组规则；
- 完成 RQ-实验映射表和初版运行说明。

### M2：初步结果

- 完成长度、GC、N 含量和缺失值分析；
- 统计已知 -10/-35 box 和 UP element 的位置/保守度；
- 生成数据质量报告和第一版可视化；
- 固化预处理命令与数据版本。

### M3：中期结果

- 运行全体 MEME；
- 运行 DREME/STREME 作为补充对照；
- 输出 motif 文件、sequence logo、FIMO 命中表和初步已知元件对比；
- 准备中期检查材料。

### M4：完整实验

- 完成 sigma 类型、物种和数据集分组 motif；
- 完成 motif 间距和排列顺序分析；
- 完成跨物种、跨数据集一致性；
- 完成强度关联和 motif 组合模式两项扩展；
- 完成消融、负对照、重采样/多种子和错误案例分析。

### M5：最终成果

- 完成报告、图表、结论和局限性说明；
- 明确回答 RQ1-RQ3；
- 完成可复现仓库、运行说明和答辩 PPT；
- 进行一次从干净环境开始的复现演练。

## 6. 协作节奏

每个工作单元都必须有：任务目的、输入、输出、验证方式、责任人、当前状态和下一步。推荐通过 GitHub Issue/Projects 或等价在线文档管理任务；每次阶段性合并前进行至少一名成员的交叉审阅。
