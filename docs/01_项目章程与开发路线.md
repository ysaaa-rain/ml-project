# 项目章程与开发路线

## 1. 项目成功标准

项目不以某一个固定分数作为唯一目标，而以“问题定义清楚、数据来源可追溯、实验链闭合、结论有证据、代码可复现、协作可检查”为成功标准。

最终至少应达到以下结果：

- 覆盖多个物种，并按 sigma 因子类型建立可审计的分组；
- 有完整的大模型 embedding、聚类/检索、局部区域解释和跨数据集验证结果；
- 用少量 PWM/MEME/FIMO 对照解释嵌入结构，而不是只展示 UMAP 图；
- 用随机/打乱背景、重复种子或重复数据抽样检验发现结果是否稳定；
- 对 RQ1-RQ3 给出明确、有限度、可由图表复核的结论；
- 主要实验与图表围绕 DNA 大模型展开；传统算法控制在一组可解释基线，强度关联和组合模式降为低优先级；
- 每个结果都能追溯到输入数据版本、配置、命令、代码提交和输出文件。

## 2. 技术路线

~~~text
公开数据与元数据
        ↓
启动子序列标准化、去重、分组、背景构造
        ↓
M2 EDA：长度、GC、来源偏差和已知元件粗略位置
        ↓
M3 大模型主线：冻结 DNA 模型 sequence/token embedding
        ↓
无监督聚类 + 近邻检索 + σ 因子结构诊断
        ↓
局部窗口/遮挡分析：定位驱动表示差异的序列区域
        ↓
M4 跨物种/跨数据集验证
        └── 小型解释基线：PWM + 一次 MEME/STREME/FIMO 对照
        ↓
M5 报告、可视化、答辩材料和可复现仓库
~~~

## 3. 基线与对照体系

### 3.1 主模型

第一轮已锁定 `InstaDeepAI/nucleotide-transformer-v2-50m-multi-species`，revision 为 `f1ff02bacb08d292ee9c3e227356d692055ac50d`，冻结参数并采用 mean pooling。DNABERT-2 只作为模型不可用时的备选；若真实数据量、标签质量和资源允许，再增加轻量探针、对比学习或 LoRA。

### 3.2 传统代码基线

仓库已锁定 `baselines/memesuite-lite`，并已有 B0 PWM demo。后续只补一次 MEME/STREME + FIMO 对照；不继续展开多个传统工具、参数网格或独立传统主线。

### 3.3 模型与基线

| 编号 | 模型/对照 | 用途 |
| --- | --- | --- |
| L0 | 冻结 DNA 大模型 sequence embedding | 主表示基线，生成每条启动子的向量 |
| L1 | embedding 聚类与近邻检索 | 主无监督发现模型 |
| L2 | token/window embedding 与遮挡分析 | 定位重要局部区域并形成候选模式 |
| L3 | 轻量探针或对比学习 | 诊断 σ 因子信息；数据和资源允许时开展 |
| B0 | -10/-35 box 共识/PWM 扫描 | 已实现的最小传统基线 |
| B1 | 一次 MEME 或 STREME + FIMO | 验证大模型候选区域和已知元件，不做多套传统算法铺陈 |
| B2 | embedding + 少量 motif 特征 | 仅用于检查传统解释特征是否带来补充 |
| N0 | 保持长度与碱基组成的随机/打乱序列 | 检查统计显著性和假阳性 |

DNA 预训练模型是主要运行环境。第一轮先冻结参数，之后视真实数据量和资源决定是否加入轻量微调。MEME Suite 和 memesuite-lite 只承担少量传统解释与验证，不再是项目主要计算路线。

## 4. Benchmark 与大众评测方式

本项目采用“多指标、分层验证”而不是只报告一个 motif 数量。主指标如下：

| 维度 | 指标 | 解释 |
| --- | --- | --- |
| 表示结构 | silhouette、聚类稳定性、kNN 一致性 | embedding 是否形成可重复结构 |
| 分组信息 | ARI/NMI、轻量探针 macro-F1、效应量 | embedding 是否包含 σ 因子相关信息 |
| 局部解释 | 遮挡前后向量变化、重要窗口稳定性、与已知位点重合 | 大模型差异能否定位到具体序列区域 |
| 已知元件恢复 | PWM/FIMO 重合率、precision/recall/F1 | 小型传统基线能否解释大模型候选区域 |
| 统计显著性 | motif E-value、FIMO p-value/q-value、背景对照差异 | 结果是否可能由随机序列造成 |
| 位置规律 | 元件相对 TSS 的位置分布、间距中位数/IQR、KS/Wasserstein 等分布差异 | 是否存在稳定的空间组织 |
| 类型差异 | 分组 motif 组成差异、效应量、校正后显著性 | sigma 类型是否有特异模式 |
| 跨来源稳定性 | motif 相似性、出现率差异、排序相关、Jaccard/聚类一致性 | 模式是通用还是数据集特异 |
| 随机稳定性 | 多随机种子/重采样下的发现率和置信区间 | 结果对抽样是否敏感 |
| 表示对照 | embedding-only、传统基线、二者融合 | 主结果是否真正来自大模型表示 |

评测协议：

1. 发现数据与验证数据按物种或数据集隔离，避免把同源序列同时放入发现和验证集合。
2. 所有组比较使用同一序列窗口、同一背景构造和记录完整的参数。
3. 至少设置一个保持长度和碱基组成的负对照；必要时增加 dinucleotide-preserving shuffle。
4. 每个关键实验记录随机种子、输入文件哈希、软件版本和完整命令。
5. 对多 motif、多位置、多组比较使用明确的多重检验校正，并在报告中区分探索性结果和验证性结果。
6. 结果表同时报告样本数、阈值、效应量和不确定性，避免只展示最优结果。
7. 大模型评测以 embedding-only 为主，传统基线和 combined 各保留一组；UMAP/PCA 只作展示，不单独作为有效性证明。

## 5. 分阶段开发流程

### M1：问题分析和数据审计

- 确认数据源、许可证/使用条件和可下载方式；
- 确定物种、sigma 类型、TSS/启动子坐标和强度标签字段；
- 建立统一 FASTA header 和 metadata schema；
- 设计去重、质量过滤和分组规则；
- 完成 RQ-实验映射表和初版运行说明。

### M2：初步结果

- 完成长度、GC、N 含量和缺失值分析；
- 统计已知 -10/-35 box 和 UP element 的位置/保守度；
- 生成数据质量报告和第一版可视化；
- 固化预处理命令与数据版本。
- 审计一个 DNA 预训练模型的许可证、revision、输入长度和本机资源需求。

### M3：中期结果

- 用冻结模型完成 embedding smoke test，并保存模型与输入追踪信息；
- 提取完整 sequence embedding，完成聚类、近邻检索和第一版跨组分析；
- 在可控样本上生成 token/window 表示，验证局部解释流程；
- 准备中期检查材料。

### M4：完整实验

- 完成 σ 因子、物种和数据集在嵌入空间中的差异分析；
- 完成重要局部窗口及其跨来源稳定性分析；
- 完成跨物种、跨数据集的聚类、检索和局部模式复核；
- 只运行一组 PWM/MEME/FIMO 传统解释基线及一组融合对照；
- 完成消融、负对照、重采样/多种子和错误案例分析。

### M5：最终成果

- 完成报告、图表、结论和局限性说明；
- 用大模型证据链明确回答 RQ1-RQ3，并说明传统基线只承担解释作用；
- 完成可复现仓库、运行说明和答辩 PPT；
- 进行一次从干净环境开始的复现演练。

## 6. 协作节奏

每个工作单元都必须有：任务目的、输入、输出、验证方式、责任人、当前状态和下一步。推荐通过 GitHub Issue/Projects 或等价在线文档管理任务；每次阶段性合并前进行至少一名成员的交叉审阅。
