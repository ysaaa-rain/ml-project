# N1 背景复核与课程 motif 输入准备

日期：2026-09-28。范围：RegulonDB 的 TSS 对齐 discovery 子集；本次只准备全序列和 sigma 分组输入，尚未运行 STREME/MEME/DREME 或 FIMO。

## 发现与修复

旧版二核苷酸打乱在随机选边时直接按探索顺序重建序列；当图有分叉，这个顺序可能不是合法的欧拉路径，校验失败后会退回原序列。旧 N1 FASTA 中，RegulonDB TSS 子集 **2,860/3,807** 条与原序列完全相同；来源原生全量数据 **3,277/4,489** 条相同。原实现虽然保留了二核苷酸计数，却没有形成有效的随机对照。

已修正为在回溯时收集路径、反向重建；对新准备的 3,807 条序列，**3,807 条均与原序列不同，且逐条验证了二核苷酸计数相同**。这是随机欧拉路径采样，不声称在所有可能重排中均匀抽样。旧 `data/processed/*/background_dinucleotide.fasta` 和依赖它们或旧代码产生的 N1 校准应视为历史产物；旧文件保留供对照，不用于新实验。

## B0 受影响结果

同一批 3,807 条真实序列、相同种子 `20260922`、相同完美共识阈值 `10.354950219366033` 下，旧/新 N1 背景的命中分别为 **505/3,807（13.265%）** 和 **554/3,807（14.552%）**。两者都高于预设的 5% 目标。由于阈值均只能取完美共识分数，真实序列上的 557 个 B0 命中及正向位置中位数（-10 为 -13 bp、-35 为 -33 bp）未变；这些仍只是探索性位置描述，不是 FIMO 显著性结果。修复后的完整校准、扫描、位置表在本地 `results/baseline_b0_regulondb_tss_n1fix_20260928/`，没有覆盖 9 月 22 日目录。来源原生全量 B0 尚未重算，其旧 N1 校准不能作为当前对照结论。

新 `b0_calibration.json` SHA256：`df0508705c6018d45b8fe95e7ff9418ded97685ad4ab5ef5dd85fc8019fa0678`。新旧 `known_element_hits.tsv` 的 SHA256 均为 `66642e92d0e69a793355268741674ed7e5e86c79bb0e53ae1f37c7576d96839e`，因此真实命中表逐字节一致。

## 已锁定的 motif 输入

运行 `experiments.prepare_motif_inputs`，只接受同一来源、同一 discovery split、TSS 已标注且统一 `[-60,+20]` 的 81 bp 序列；未知 sigma 进入全序列集，但不单独成组。每组至少 50 条，当前 6 个已知 sigma 组全部达到门槛。每条真实序列配一条修复后的 N1 控制序列，FASTA、样本量和 SHA256 记录在被 Git 忽略的 `results/motif_inputs_regulondb_tss_n1fix_20260928/motif_input_manifest.json`。

```bash
python -B -m experiments.prepare_motif_inputs \
  --input data/processed/m1_regulondb_tss_20260922/promoters_clean.tsv \
  --output-dir results/motif_inputs_regulondb_tss_n1fix_20260928 \
  --source regulondb --upstream 60 --downstream 20 \
  --min-group-size 50 --seed 20260922

python -B -m experiments.calibrate_b0 \
  --input data/processed/m1_regulondb_tss_20260922/promoters_clean.tsv \
  --output-dir results/baseline_b0_regulondb_tss_n1fix_20260928 \
  --shuffle-method dinucleotide --seed 20260922 \
  --target-false-positive-rate 0.05 --background-per-length 2000
```

输出目录已有文件时，准备脚本会拒绝覆盖；复现时应选一个新的本地目录。B0 的扫描和位置汇总命令沿用[运行说明](运行说明.md) §3.3，只需改为新的校准与输出目录。

## 下一步工具边界

本机 `experiments.preflight` 的记录保存在 `results/motif_inputs_regulondb_tss_n1fix_20260928/preflight.json`，其中 `meme`、`dreme`、`streme`、`fimo` 均为 `available=false`；当前 WSL 也没有已安装的 Linux 发行版。MEME Suite [官方安装说明](https://meme-suite.org/meme/doc/install.html)对 Windows 推荐 Docker 或 WSL。仓库子模块 `memesuite-lite` 包含 FIMO/Tomtom 的 Python 重实现，不能代替老师要求的全序列与分组 de novo motif 发现。

工具可用后，应先记录软件版本并对全序列和上述 6 个组分别运行发现程序；[STREME 官方文档](https://meme-suite.org/meme/meme_5.5.8/doc/streme.html?man_type=cmd)支持显式的主序列和控制序列 FASTA。再用 [FIMO 官方文档](https://meme-suite.org/meme/doc/fimo.html?man_type=cmd)规定的 q-value 阈值定位 motif，统计位置、间距与排列。当前文件只完成输入准备，不产生 motif、FIMO 命中或跨来源结论。
