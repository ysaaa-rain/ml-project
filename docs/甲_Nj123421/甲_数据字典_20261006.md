## 2. 目录结构

```text
pr01_02_data_v2/
├── 8 个全局文件（见第 5 节）
├── tjupan_<物种>/main/          ← 6 个 TJU 物种
├── regulondb_ecoli/core/
├── regulondb_ecoli/extended/
└── dbtbs_bsub/core/
```

每个「来源/层」目录里有 12 个文件（TJU）或 11 个（RegulonDB/DBTBS），命名规律：

```text
<划分>.<类型>.fasta        ← 序列文件，共 9 或 8 个
sequence_master.tsv        ← 该来源/层的序列身世表
sigma_associations.tsv     ← 该来源/层的 σ 关联表
source_record_mapping.tsv  ← 该来源/层的溯源表
```

`regulondb_ecoli` 和 `dbtbs_bsub` 另有 `sigma/<组名>/` 子目录，按 σ 分组存放。

## 3. 三个划分（`split` 列）

**这是最容易搞错的地方。**

| 划分 | 文件前缀 | 用途 | 禁令 |
| --- | --- | --- | --- |
| **discovery** | `discovery.*` | 找规律、发现 motif | 只能用它发现，不能拿它验证 |
| **development** | `development.*` | 调参数、定阈值 | 只能用它调参 |
| **holdout** | `holdout.*` | 最终验证 | **只能用一次，不得用于调参或重发现** |

另有 `external_validation.*`，只出现在 RegulonDB 和 DBTBS，是 holdout 中与其他来源不重叠的子集，用于跨数据集验证。

**划分是按同源簇做的**：高度相似的序列整体进入同一个划分，不会跨边。`sequence_master.tsv` 的 `leakage_group` 列记录了这个分簇。

## 4. 三类序列（文件名里的类型）

| 类型 | 是什么 | 哪些来源有 |
| --- | --- | --- |
| `positive` | 启动子正样本（label=1） | 全部 |
| `natural_control` | 天然对照，数据集标为负类（label=0） | 只有 TJU 六物种 |
| `dinucleotide_null` | 把正样本序列打乱生成的对照（保持二核苷酸组成） | 全部 |

**注意**：`natural_control` 是数据集自带的负类，**不能默认等同于无偏背景**——六物种正负样本存在 GC 系统差异。`dinucleotide_null` 是打乱生成的随机对照，**也不等同于天然非启动子**。两者用途不同，报告里必须分开称呼。

## 5. 全局文件与逐列说明

### 5.1 `manifest.json`

总台账。关键字段：

| 字段 | 内容 |

| `status` | 数据状态：`data_rebuilt_no_motif_experiment`（已重建、未跑正式 motif 实验） |

### 5.2 `sequence_master.tsv`（17 列，22,594 行）

**所有序列的统一身世表**，一行 = 一条序列。

| 列名 | 含义 | 取值 |
| --- | --- | --- |
| `sequence_id` | 唯一编号 | `<来源>_<层>_<哈希>` |
| `species` | 物种 | `escherichia_coli` 等 |
| `source` | 来源 | `tjupan_*` / `regulondb_ecoli` / `dbtbs_bsub` |
| `sequence` | DNA 序列 | 81 bp，仅 A/C/G/T |
| `length` | 序列长度 | 全部为 81 |
| `local_tss_index` | TSS 在序列内的 1-based 位置 | 全部为 **61** |
| `window_offsets` | 窗口相对 TSS 的范围 | 全部为 **[-60,20]** |
| `split` | 所属划分 | `discovery` / `development` / `holdout` |
| `tier` | 数据层级 | `main`（TJU）/ `core` / `extended` |
| `label` | 正负标签 | `1` = 正样本；`0` = 天然对照 |
| `orientation` | 输入序列方向 | `upstream_transcription_forward_accepted`（TJU）/ `transcription_forward`（RegulonDB、DBTBS） |
| `coordinate_evidence` | 坐标证据来源 | `PromLoop_author_statement_accepted_by_project` / `exact_reference_window_match` / `binding_sequence_and_location_verified` |
| `leakage_group` | 同源簇编号 | 划分隔离的依据 |
| `source_records` | 对应原始记录 ID | 列表 |
| `assembly` | 参考基因组版本 | 多数为空 |
| `genomic_strands` | 基因组链 | 多数为 `[]` |
| `genomic_tss_values` | 基因组 TSS 坐标 | 多数为 `[]` |

已核对的分布：

| 列 | 取值分布 |
| --- | --- |
| `split` | discovery 15,774 / holdout 4,623 / development 2,197 |
| `tier` | main 18,349 / core 2,225 / extended 2,020 |
| `label` | 1 → 13,953 / 0 → 8,641 |
| `orientation` | `upstream_..._accepted` 18,349 / `transcription_forward` 4,245 |
| `coordinate_evidence` | `PromLoop_...` 18,349 / `exact_reference_window_match` 3,813 / `binding_sequence_and_location_verified` 432 |

### 5.3 `sigma_associations.tsv`（7 列，22,757 行）

**启动子与 σ 因子的关联表**，一行 = 一条关联。

| 列名 | 含义 |
| --- | --- |
| `sequence_id` | 关联到哪条序列 |
| `sigma_raw` | 来源里的原始 σ 名称（如 `Sigma70`、`SigA`、`unknown`） |
| `sigma_id` | 规范化 ID（如 `escherichia_coli:Sigma70`） |
| `source_record_id` | 原始记录 ID |
| `promoter_confidence` | 启动子证据等级 |
| `evidence` | 证据类型列表 |
| `sigma_association_evidence` | σ 关联证据状态（多为 `source_label_not_independently_verified`） |

**一行不等于一条序列**：一条序列可能被多个 σ 认领（多行），也可能在原始记录里重复出现。因此本表行数（22,757）**大于** `sequence_master.tsv` 的行数（22,594）。

### 5.4 `source_record_mapping.tsv`（19 列，22,757 行）

**溯源表**，把每条派生记录追回原始文件。

关键列：`record_id`（原始记录 ID）、`source_file`（原始文件路径）、`source_file_sha256`（原文件哈希）、`input_orientation`（输入序列方向）、`strand`（基因组链）、`tss`、`location`、`absolute_position`、`bold_positions`（DBTBS 网页粗体位置）、`confidence`、`evidence`、`sigma`、`tier`。

### 5.5 `exclusions.tsv`（20 列，395 行）

被排除的记录，列结构与 `source_record_mapping.tsv` 相同，**多一列 `reason`**。

7 类原因共 395 条，详见 [甲_排除记录汇总_20261006.md](甲_排除记录汇总_20261006.md)。

### 5.6 `leakage_links.tsv`（3 列，3,430 行）

同源关系表，一行 = 一对被判为同源的序列。

| 列名 | 含义 |
| --- | --- |
| `a` / `b` | 两条序列的 `sequence_id` |
| `method` | 判定方法（`full_query_fitting_edit_distance_le8_both_orientations`） |

跨划分的同源对数量为 **0**（`manifest.json` 的 `cross_split_leakage_groups`）。

### 5.7 `tju_sigma_annotation_candidates.tsv`（6 列，772 行）

TJU 序列与辅助来源 σ 注释的关联候选。

| 列名 | 含义 |
| --- | --- |
| `tju_sequence_id` | TJU 序列 ID |
| `auxiliary_sequence_id` | 辅助来源（RegulonDB/DBTBS）对应序列 ID |
| `sigma_candidates` | 候选 σ 列表 |
| `same_orientation` | 方向是否一致 |
| `source` | 辅助来源 |
| `status` | 状态，固定为 `exact_source_mapping_candidate_not_independent_validation` |

**这不是独立验证**：两边序列完全相同，只是同名映射，不能拿来当「验证成功」的证据。

### 5.8 `sigma_group_summary.tsv`（7 列，19 行）

σ 分组的样本量与可用性判定。列：`source`、`sigma`、`discovery`、`development`、`holdout`、`single_sigma_sequences`、`eligibility`。

详见 [甲_σ组可用性清单_20261006.md](甲_σ组可用性清单_20261006.md)。

## 6. 字段口径说明

| 项 | 说明 |
| --- | --- |
| 三个划分 | `discovery` 用于发现，`development` 用于调参，`holdout` 用于最终验证，三者不可混用 |
| `tier` | `core` 只含 Strong/Confirmed 证据；`extended` 额外含 Weak 证据。两者证据等级不同 |
| `orientation` vs `input_orientation` | `orientation` 在 `sequence_master.tsv`，指输入序列方向；`input_orientation` 在 `source_record_mapping.tsv`，指原始记录方向。序列已统一为转录方向，不再按 `strand` 反向互补 |
| `window_offsets` | 本版本全部为 `[-60,20]`（81 bp），不存在多窗口重复计数 |
| 多 σ 记录 | `sigma_associations.tsv` 中一条序列可对应多行；`sigma_group_summary.tsv` 的计数只含单标签序列 |

## 7. 已知限制

以下 5 条来自 `manifest.json` 的 `known_limits`，是报告里必须交代的局限性：

| 原文 | 中文说明 |
| --- | --- |
| TJU alignment relies on upstream statement, not per-record genomic verification | TJU 的 TSS 对齐**采信 PromLoop 的发布说明**，没有逐条回到基因组独立核验 |
| DBTBS .2 matches accepted binding intervals; exact 2005 genome flank identity unverified | DBTBS 用的 NC_000964.2 与接受的结合区间匹配，但**不能证明与 2005 年原版完全一致** |
| promoter confidence does not prove sigma association confidence | **启动子证据强 ≠ σ 关联证据强**，两者是独立的证据维度 |
| small sigma groups require post-split eligibility check | 小 σ 组必须先查样本量（见 σ 可用性清单），不能直接分析 |
| fitting edit-distance threshold is an operational isolation rule, not proof of biological independence | 相似度阈值是**操作规则**，不等于生物学上的独立性证明 |
