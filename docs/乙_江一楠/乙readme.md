## 二、口径：算之前先定死，不边看结果边改

这部分是乙最容易被质疑的地方，所以写在最前面。全部规则**在跑任何统计之前就固定**，
脚本里是常量，不是临时判断。

| # | 规则 | 取值 | 理由 |
| --- | --- | --- | --- |
| 1 | 位置换算 | 偏移 = 序列内 1-based 下标 − 61；TSS 本身为 0，上游为负 | 本版固定 81 bp、TSS 第 61 位 |
| 2 | 元件串 | -35 box = `TTGACA`，-10 box = `TATAAT` | M2 用**教科书已知答案**比对，不是自己找暗号 |
| 3 | 期望窗口 | -35 盒偏移 `[-37, -32]`；-10 盒偏移 `[-12, -7]` | 沿用本项目既有约定（旧 M3 的 `input_start_window_1based` 24–29 / 49–54），不是我新造的 |
| 4 | 匹配规则 | 主口径**精确匹配（0 错配）**；另报 ≤1 错配敏感性 | 问答记录要求"拿固定字母扫一遍"；但只报精确匹配会把结论说死，所以并报敏感性 |
| 5 | 扫描链向 | **只扫正向** | 本版序列已统一为转录方向（甲_数据字典·字段口径说明），再扫反向互补等于把错误方向的命中当证据 |
| 6 | 统计用划分 | 只用 **discovery**；`holdout` 一律不碰 | 三条红线之一 |
| 7 | σ 分组 | 只取**单标签**序列（一条序列只挂一个非 unknown 的 σ），且只用 `core` 层 | 与 `sigma_group_summary.tsv` 口径一致；多标签不硬选，extended 证据等级不同不混算 |
| 8 | 背景 | 直接用数据自带的 `*.dinucleotide_null.fasta` | 与正样本**逐文件配对**、同划分、同长度、二核苷酸组成保持，比自己另造背景更干净 |
| 9 | 跨来源比较 | **不做** | RegulonDB（大肠杆菌）与 DBTBS（枯草芽孢杆菌）物种不同、σ 命名体系不同，直接比会把物种效应当成 σ 效应 |
| 10 | 样本量分级 | 沿用甲_σ组可用性清单：总数 ≥50 且发现 ≥30 且留出 ≥20 才算可做正式结论 | 不重新评级 |
| 11 | "只能描述"的组 | 只报 n / 均值 / 中位数，**不报 p 值、不报效应量** | 甲的口径是"只报样本量，不做统计" |
| 12 | 效应量 | 连续量报中位数差 + bootstrap 95%CI + 秩双列相关；比例报风险差 + 95%CI + 比值比 | 问答记录要求"必须报差多少，不能只报显著不显著" |
| 13 | 多重比较 | Benjamini–Hochberg 校正，同时给原始 p 与 q | 一次比较十几个组 |

### 第 3 步：质检 + GC / 长度 / 缺失 ✅ 已完成

**干什么**：查长度、GC 含量、缺失、重复；按来源/物种/σ 组分组画图。

**为什么**：GC 是 M2 里唯一能跨所有来源比较的量；重复和缺失不写清楚，
后面所有"组间差异"都可能是重复样本造成的假象。

**怎么做**：长度分布、非法字符、关键列缺失、完全重复、反向互补重复、跨划分重复逐个查；
GC 按 来源×物种×标签、按 σ 组、按 TJU 正/天然对照分别统计。

**做到什么程度**：每个分组都有 n / 均值 / 标准差 / 中位数 / 四分位 / 极值。

**结果要点**：

- 长度**没有分布可画**：22,594 条全部 81 bp，这是构建时固定的窗口，不是数据巧合。
  （甲在第 4 步已排除 4 条 80 bp 的对照。）所以我没有画长度图——画出来只是一根柱子。
- 非法字符 0 条；关键列缺失 0 条；`local_tss_index` 全部 61。
- 同（来源,划分）内完全重复：**只有 1 对**，是同一条序列同时出现在 RegulonDB 的 `core` 和 `extended` 两层。
- 跨来源同划分的完全相同序列 **1,169 条**（DBTBS↔TJU 枯草 409 条、RegulonDB↔TJU 大肠杆菌 760 条）。
  这是**设计允许**的同物种跨数据集重叠，不是泄漏；但按规范它们只能用于注释，**不能算独立验证**。
- 反向互补重复 **8 对**；甲的泄漏表 3,430 对里**跨划分 0 对**，与清单登记一致。
- **TJU 正样本 GC 在六个物种里全部低于天然对照**，中位数差 −4.9 到 −13.6 个百分点。
  这印证了甲在数据字典里的提醒："六物种正负样本存在 GC 系统差异"。

### 第 4 步：-10/-35 box 位置分布 ✅ 已完成

**干什么**：拿教科书上写死的 `TTGACA`、`TATAAT`，在序列里扫一遍，看它们出现在离起点多远的地方。

**为什么**：这是问答记录里说"这次唯一能做对的地方"——因为数据带真实起点，
能算出"在起点上游多少 bp"这种有生物学意义的坐标。

**怎么做**：精确匹配（0 错配）扫正向，命中起始位换算成 TSS 相对偏移；
主结果只做 RegulonDB core（按问答记录）；同时算逐位置碱基组成与信息量。

**结果要点**（RegulonDB core，discovery，n = 1,284）：

| 元件 | 精确命中 | 众数偏移 | 上游占比 | 落在期望窗口 |
| --- | ---: | ---: | ---: | ---: |
| -35 box `TTGACA` | 42 条（3.27%） | **−36** | 76.7% | 37.2% |
| -10 box `TATAAT` | 74 条（5.76%） | **−12** | 92.2% | 41.6% |

**两个众数偏移恰好落在期望窗口的起点上（−36 和 −12）**，这是 TSS 对齐正确的一个旁证。

逐位置信息量（vs 均匀分布）在 **−11 位取到最大值 0.221 bits**，
−10 窗口内平均 0.073 bits，−35 窗口内平均 0.026 bits ——
即**−10 区的信息量明显强于 −35 区**，与教科书 σ70 启动子的强弱关系一致。

### 第 5 步：背景校准 ✅ 已完成

**干什么**：用打乱序列扫一遍，看有多少命中是纯靠运气撞上的。旧数据里这个比例是 14.5%。

**为什么**：不校准就报"42 条命中"，等于不知道这个数是不是随机也能撞出来。

**怎么做**：**直接用数据自带的 `dinucleotide_null`**（二核苷酸保持打乱），
逐文件与正样本配对、同划分，算命中率差、富集倍数、Fisher 检验。

**结果要点**（RegulonDB core，discovery）：

| 元件 | 正样本命中率 | 打乱背景命中率 | 超出 | 富集 | Fisher p |
| --- | ---: | ---: | ---: | ---: | ---: |
| -35 `TTGACA`（精确） | 3.27% | 2.57% | +0.70 pp | 1.27× | 0.3485 |
| -10 `TATAAT`（精确） | 5.76% | 5.22% | +0.55 pp | 1.10× | 0.6034 |
| -35 `TTGACA`（≤1 错配） | 42.91% | 37.07% | +5.84 pp | 1.16× | 0.0029 |
| -10 `TATAAT`（≤1 错配） | 59.35% | 50.62% | +8.72 pp | 1.17× | 1.06e−05 |

**这是一条必须如实报的结论：按问答记录要求的"精确匹配"口径，
两个教科书元件在 RegulonDB core 里都**没有**显著高于打乱背景**（p = 0.35 / 0.60，
置信区间跨 0）。放宽到 ≤1 错配后才显著，但富集也只有 1.16–1.17 倍。

打乱对照本身的 GC 与正样本**逐文件完全相同（差 0.000 pp）**，说明这套背景是干净的。

**关于旧数据的 14.5%**：这个数字的定义没有在仓库任何地方登记（我把整个仓库找遍了），
窗口口径也不一样（旧版是 101 bp / TSS 第 81 位），**因此无法复现、也无法直接比较**。
我只报本次重算的值。详见结论段的说明。

### 第 6 步：σ 组间差异（含效应量）✅ 已完成

**干什么**：比不同 σ 组之间的 GC 和元件命中率差别。

**为什么**：问答记录明确要求"**必须报'差多少'，不能只报'显著不显著'**"。

**怎么做**：只在**同一来源内部**比较（RegulonDB 内以 Sigma70 为参照、DBTBS 内以 SigA 为参照）；
报中位数差 + bootstrap 95%CI + 秩双列相关，或风险差 + 95%CI + 比值比；
多重比较做 BH 校正。

**结果要点**：

- **RegulonDB 内**：Sigma32 的 GC 比 Sigma70 高 **+3.09 个百分点**（95%CI [1.23, 6.17]，q = 0.0064）；
  Sigma38、Sigma24 与 Sigma70 基本无差别（差 0.00 pp，q > 0.85）；Sigma54 样本少、区间很宽。
- **DBTBS 内**：SigB / SigE / SigG / SigK 的 GC 比 SigA 高 **+4.9 到 +6.2 个百分点**
  （q = 0.0014–0.0034，效应量 r = 0.41–0.49），方向一致、量级稳定。
- **元件命中率**：RegulonDB 内各组的 −10 命中率都低于 Sigma70（风险差 −3.6 到 −7.2 pp），
  但**所有 q 值都远大于 0.05**，即"看起来低"但样本量不足以支持差别。
  DBTBS 的 SigA 的 −10 精确命中率高达 **26.99%**，明显高于 RegulonDB Sigma70 的 7.20%。
- **只能描述的 9 个组**（SigH、SigW、Sigma28、SigD、SigF、SigX、SigL、SigM、SigI）
  我只报了 n、均值、中位数，**没有报 p 值和效应量**。

### 第 8 步：按 σ 组的位置与间距明细 ✅ 已完成

**干什么**：把位置和间距**按 σ 组拆开**，算出框架要求的均值 / 中位数 / 范围 / 离散程度。

**为什么**：这一步是补漏。团队的报告框架
（[M1M2报告框架.md](../丙_ywg27/M1M2报告框架.md)）在 M2 结果部分要求 9 张表，
其中 **表 4-6（-10 box 位置）、表 4-7（-35 box 位置）、表 4-8（间距）** 需要逐条序列的位置信息——
**丙手上没有原始序列，填不了这三张表**，所以必须由乙提供。
另需补 **图 4-1（长度分布）** 与 **图 4-4（间距分布）**。

**怎么做**：新开脚本 `08_positions_by_sigma.py`，**不改动脚本 04 及其已核对过的产出**。
关键规则：**每条序列每个元件只取一个代表命中**（先取落在期望窗口内的，
否则取离窗口中心最近的），避免同一条序列的多个偶然命中把均值/中位数带偏。

**结果要点**：

- **序列长度恒为 81 bp**，没有分布。图 4-1 我照框架做了，但图上明确标注
  "长度由窗口定义决定，不是观测到的分布"，**避免被读成"长度高度保守"这个生物学发现**。
- **-10 box（Sigma70，n=42）位置中位数 −12.0、IQR 3.0**，命中高度集中在期望窗口附近。
- **-35 box（Sigma70，n=25）位置中位数 −35.0，但 IQR 高达 29、均值 −24.76 与中位数差 10 bp**
  ——分布右偏，**报告里引用 -35 位置必须用中位数并同时给离散程度**，只用均值会误导。
