## 3. 全窗口逐位置信息量（不依赖固定串的结果）

只看固定串会漏掉变体。所以我另外算了**每个位置的碱基偏好**：

- `info_vs_uniform`：该位置碱基分布相对均匀分布的偏离（bits）
- `info_vs_null`：该位置碱基分布相对**配对打乱背景**同位置的偏离（bits）——
  后者控制了整体碱基组成，是判断"这个位置真的有偏好"的关键指标

| 指标 | 最大值 | 位置 |
| --- | ---: | ---: |
| info vs uniform | **0.221 bits** | **−11** |
| info vs null | 0.122 bits（−11）／0.140 bits（TSS 0 位） | −11 / 0 |

| 区域 | 平均 info vs null | 最大 info vs null |
| --- | ---: | ---: |
| **-35 期望窗口 `[-37,-32]`** | 0.026 bits | 0.056 bits（@ −35） |
| **-10 期望窗口 `[-12,-7]`** | **0.073 bits** | **0.122 bits（@ −11）** |

**只描述**：整个 81 bp 窗口里有两个信息峰——一个在 **−11 位**（0.221 bits vs 均匀），
一个在 **TSS 本身（0 位）**。
**−10 区的信息量（0.073 bits 均值）约为 −35 区（0.026 bits）的 2.8 倍。**

（图见 `F6_逐位置信息量_RegulonDBcore.png`，期望窗口用红带标出。）

## 4. 为什么精确串命中率这么低？——逐位置比对给出答案

**这是本文件最重要的一节。** 精确串命中率只有 3.27% 和 5.76%，
但**这不等于"那个位置没有偏好"**。把期望窗口内每个位置"实际最常出现的碱基"
列出来，与共识串逐位比对：

### -35 box 期望窗口 `[-37,-32]`

| 偏移 | 共识碱基 | **实测最优碱基** | 实测占比 | 共识碱基占比 | 是否一致 |
| ---: | :---: | :---: | ---: | ---: | --- |
| −37 | T | **T** | 31.15% | 31.15% | ✅ |
| −36 | T | **T** | 35.28% | 35.28% | ✅ |
| −35 | G | **T** | 41.90% | 17.37% | ❌ |
| −34 | A | **T** | 37.77% | 21.81% | ❌ |
| −33 | C | **T** | 32.40% | 19.39% | ❌ |
| −32 | A | **T** | 28.74% | 27.34% | ❌ |
| | `TTGACA` | **`TTTTTT`** | | | **2/6 位一致** |

### -10 box 期望窗口 `[-12,-7]`

| 偏移 | 共识碱基 | **实测最优碱基** | 实测占比 | 共识碱基占比 | 是否一致 |
| ---: | :---: | :---: | ---: | ---: | --- |
| −12 | T | **T** | 39.56% | 39.56% | ✅ |
| −11 | A | **A** | 45.72% | 45.72% | ✅ |
| −10 | T | A | 38.40% | 32.55% | ❌（T 排第二） |
| −9 | A | **A** | 39.88% | 39.88% | ✅ |
| −8 | A | **A** | 35.83% | 35.83% | ✅ |
| −7 | T | **T** | 45.72% | 45.72% | ✅ |
| | `TATAAT` | **`TAAAAT`** | | | **5/6 位一致** |

**结论（只描述）**：

1. **-10 窗口的实际碱基偏好与教科书共识 `TATAAT` 有 5/6 位一致**，
   唯一不一致的 −10 位也是 T（32.55%）排第二、A（38.40%）第一，属于偏好宽松而不是没有偏好。
   **这说明 -10 元件确实存在于这批数据里，只是以变体形式存在，而不是精确的 `TATAAT`。**
2. **-35 窗口是"整段富 T"（`TTTTTT`），只有前两位与 `TTGACA` 一致**，
   第 3–6 位实测都偏好 T，而共识要求 G、A、C、A。
   **这说明这个位置有很强的组成偏好，但它不表现为教科书 `TTGACA` 的样式。**

**这就是"精确串命中率低"的真正原因**：教科书的 `TTGACA`/`TATAAT` 是**共有序列（consensus）**，
是每个位置上最常出现碱基的拼接，**不等于任何一条真实序列**。
真实启动子普遍带变体。**丙写报告时，必须把"精确串命中率低"和"该位置没有偏好"分开说。**

## 5. 背景校准（重算"运气命中率"）

**问答记录原话**："必须先跑一次背景校准——用随机打乱的序列扫一遍，
看看有多少命中是纯靠运气撞上的。**旧数据里这个比例是 14.5%**，新数据得重新算。"

### 5.1 背景用的是哪个

用数据自带的 `discovery.dinucleotide_null.fasta`：**n = 1,284，与正样本逐条配对**，
同长度（81 bp）、保持二核苷酸组成。
第 3 步已验证它的 GC 与正样本**逐文件完全相同（差 0.000 pp）**。

**不用 `label=0` 的天然对照做背景**——因为第 3 步已经量化出
TJU 正负样本 GC 中位数差达 −4.9 到 −13.6 pp，它是有偏背景。

### 5.2 校准结果（主口径：精确匹配）

| 元件 | 正样本命中 | 正样本命中率 | 打乱背景命中 | 背景命中率 | **超出** | 95% CI | 富集 | Fisher p |
| --- | ---: | ---: | ---: | ---: | ---: | --- | ---: | ---: |
| -35 `TTGACA` | 42 / 1,284 | 3.27% | 33 / 1,284 | 2.57% | **+0.70 pp** | **[−0.60, +2.00]** | 1.27× | **0.3485** |
| -10 `TATAAT` | 74 / 1,284 | 5.76% | 67 / 1,284 | 5.22% | **+0.55 pp** | **[−1.22, +2.31]** | 1.10× | **0.6034** |
| ≥1 个元件命中 | 114 / 1,284 | 8.88% | 97 / 1,284 | 7.55% | +1.32 pp | [−0.80, +3.45] | 1.18× | 0.2502 |

每序列命中数：-35 正样本 0.033 / 背景 0.026；-10 正样本 0.060 / 背景 0.054。

### 5.3 敏感性分析（≤1 错配）

| 元件 | 正样本命中率 | 背景命中率 | **超出** | 95% CI | 富集 | Fisher p |
| --- | ---: | ---: | ---: | --- | ---: | ---: |
| -35 `TTGACA` | 42.91% | 37.07% | **+5.84 pp** | **[+2.06, +9.62]** | 1.16× | **0.0029** |
| -10 `TATAAT` | 59.35% | 50.62% | **+8.72 pp** | **[+4.89, +12.56]** | 1.17× | **1.06e−05** |
| ≥1 个元件命中 | 77.80% | 68.85% | +8.96 pp | [+5.55, +12.36] | 1.13× | 3.48e−07 |

（≤1 错配 = 允许 1 个位置替换，6 聚体共 1 + 18 = 19 个模式串。）

### 5.4 这一节必须如实写出的结论

> **按问答记录指定的"精确匹配"口径，两个教科书元件在 RegulonDB core 里
> 都没有显著高于打乱背景**（-35：+0.70 pp，95%CI 跨 0，p = 0.35；
> -10：+0.55 pp，95%CI 跨 0，p = 0.60）。
> **放宽到 ≤1 错配后两者都显著，但富集只有约 1.16–1.17 倍，属于"弱但可测"。**

**这不是"什么都没发现"，而是一个有意义的描述性结果**，与第 4 节的逐位置比对完全自洽：

- 位置上有真实偏好（−10 窗口 5/6 位与共识一致，信息量 −11 位最高）；
- 但**精确共识串本身在真实启动子里很罕见**，所以固定串扫描的富集信号很弱。

### 5.5 关于"旧数据 14.5%"——**无法复现，报告里不能做对比**

我把整个仓库全文检索了一遍，**找不到 14.5% 的定义**（是"多少个序列至少一个命中"？
还是"多少个命中是背景命中"？还是别的口径？没有任何登记）。
而且口径本身变了：旧版（`g0_rebuild_20261004`）是 **101 bp 窗口、TSS 在第 81 位**，
本版是 **81 bp、TSS 在第 61 位**，两者的"命中率"天然不可比。

**所以：报告里只能写本次重算值，不能写"比旧数据升高/降低了多少"。**

为方便丙查证，我把本次算出的几种可能口径都列出来，但没有一种等于 14.5%：

| 口径（RegulonDB core，discovery，精确匹配） | 正样本 | 打乱背景 |
| --- | ---: | ---: |
| -35 至少一个命中 | 3.27% | 2.57% |
| -10 至少一个命中 | 5.76% | 5.22% |
| 至少一个元件命中 | 8.88% | 7.55% |
| （≤1 错配）至少一个元件命中 | 77.80% | 68.85% |
