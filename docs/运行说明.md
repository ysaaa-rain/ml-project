# 运行说明

本文件与代码同步维护。目前仓库已经提供 M1 数据构建和 M2 EDA 的可复现入口；真实外部数据下载、MEME Suite 发现和 FIMO 定位仍需在数据源审计后接入。

## 环境

~~~bash
python -m pip install -r requirements.txt
~~~

MEME Suite 的命令行工具是 motif 发现主线的外部依赖。安装方式、版本和验证命令将在 M1 环境审计后补充；没有安装时不得把本地 Python 处理结果标记为完整实验结果。

运行环境预检：

~~~bash
python -m experiments.preflight --output tmp/preflight.json
~~~

该命令记录 Python、关键 Python 包以及 `meme/streme/dreme/fimo/tomtom` 的可用性、路径和版本。只有 `meme_suite.ready=true` 时，才表示主线所需的 MEME、STREME、FIMO 和 Tomtom 已全部检测到。

## M1/M2 数据构建与 EDA

输入表可以是 CSV 或 TSV，至少包含以下字段：

~~~text
sequence_id  species  source_dataset  sequence
~~~

推荐同时提供 `sigma_factor_type`、`evidence_level` 和 `promoter_strength`。示例输入位于 `tests/fixtures/sample_promoters.tsv`，仅用于代码 smoke test。

运行完整基础流程：

~~~bash
python -m pytest -q
python -m experiments.run_m1 --config configs/m1_demo.yaml
~~~

配置文件中的相对路径以仓库根目录为基准。流程会输出：

- `promoters_clean.tsv`：标准化、质量过滤和精确去重后的 metadata；
- `promoters_clean.fasta`：供后续 MEME/FIMO 使用的序列；
- `background_shuffled.fasta`：N0 单核苷酸组成保持背景；
- `background_dinucleotide.fasta`：N1 二核苷酸组成保持背景；
- `quality_report.json`：输入/输出数量、缺失/非法字符、分组和长度/GC 摘要；
- `group_summary.tsv`：物种、数据源、σ 因子和发现/验证 split 的统计；
- `position_composition.tsv`：按序列位置汇总的碱基组成；
- `length_gc_distribution.png`、`sigma_factor_counts.png`：M2 基础图形；
- `m1_manifest.json`：本次配置和产物索引。

`quality_report.json` 还会记录输入文件和配置文件的 SHA256，以及 TSS 窗口化和近同源聚类的完整报告；`m1_manifest.json` 同时保存环境快照，便于后续复现实验。

### 负对照：N0 与 N1

两个背景使用同一个随机种子生成，因此两者之间唯一的差别是打乱算法本身：

- **N0（单核苷酸保持）** 只保证长度和单碱基组成一致，会破坏二核苷酸频率。真实序列在这种背景下通常显得"更像 motif"，因此仅凭 N0 显著的结论证据强度较弱。
- **N1（二核苷酸保持）** 采用 Altschul–Erikson 打乱，同时保持单核苷酸和二核苷酸组成。这是更严格的对照，正式 E-value 应以它为准。

可用 `--background-method` 指定其中之一，或在配置中用 `background_methods` 同时生成两份。

### TSS 窗口与链方向标准化

motif 的相对位置只有在统一坐标下才可比。启用后每条序列被截取为相对 TSS 的窗口 `[-upstream, +downstream]`，负链记录做反向互补，因此"上游"在两条链上含义一致：

~~~bash
python -m preprocessing.build_dataset \
  --input data/raw/promoters_metadata.tsv \
  --output-dir data/processed/m1 \
  --validation-source dbtbs \
  --background-replicates 10 \
  --tss-window 60 20 \
  --homology-clustering
~~~

或在配置文件中：

~~~yaml
tss_window:
  upstream: 60
  downstream: 20
tss_column: tss_position
strand_column: strand
~~~

要求输入表包含 `tss_position`（1-based）和 `strand`（`+`/`-`，也接受 `1`/`-1`、`forward`/`reverse` 等写法）。
窗口超出序列两端、缺少 TSS 或缺少链方向的记录会被**丢弃并在报告中按原因计数**，不会被静默截断或平移。
`upstream` 恰好等于 TSS 坐标时窗口从序列首端开始，属于合法情况。

输出新增 `window_start_1based`、`window_end_1based`、`tss_offset_in_window`、`window_strand` 四列，
完整丢弃原因见 `quality_report.json` 的 `tss_windowing` 字段。

### 近同源聚类与泄漏控制

只按 `source_dataset` 划分 discovery/validation 时，近同源序列可能被分到两侧。同源序列共享 motif，
这种泄漏会抬高跨数据集一致性，使 RQ3 无法回答。启用聚类后：

1. 按序列相似性把记录聚成同源簇（k-mer 草图做候选预筛，再用无比对同一性精确判定，默认阈值 0.90）；
2. 以簇为单位投票决定归属，**整簇划到同一侧**，保证没有任何簇横跨两侧；
3. 被迫改派的簇会逐条记入 `quality_report.json` 的 `homology_split.reassigned_clusters`，便于复核。

`homology_split.leakage_violations_after` 必须为 `0`；这是脚本自行验证的不变量，不是假设。

~~~yaml
homology_clustering: true
identity_threshold: 0.90
kmer_size: 15
~~~

同时覆盖两项新功能的示例配置见 `configs/m1_windowed_demo.yaml`。

## B0 已知核心元件扫描

B0 提供一个可解释的共识 PWM 基线，用于扫描 `TTGACA`（-35 box）和 `TATAAT`（-10 box），默认正负链均扫描。

**阈值必须先校准，不能直接使用历史默认值。** 旧默认 `--min-score 2.0` 远低于满分，
在 demo 数据上会命中 6/6 条真实序列和 12/12 条打乱背景序列，即完全没有区分度。
原因是评分尺度接近二值：完美匹配约 10.355，错配一个碱基就降到约 6.514。

校准按**序列长度**分别进行，因为假阳性率强烈依赖窗口数量（30 bp 的 6-mer 假阳性率远高于 100 bp）：

~~~bash
python -m experiments.calibrate_b0 \
  --input data/processed/m1/promoters_clean.tsv \
  --output-dir results/b0_calibration \
  --shuffle-method dinucleotide \
  --background-per-length 5000
~~~

该命令对每个长度生成大量打乱背景，在评分网格上搜索**满足目标假阳性率的最小阈值**，
并写出 `b0_calibration.json`（决策记录，含预注册阈值与达标情况）、
`b0_threshold_table.tsv` 和 `b0_score_distribution.png`。

然后用校准结果扫描：

~~~bash
python -m experiments.known_element_scan \
  --input data/processed/m1/promoters_clean.tsv \
  --output-dir results/b0_known_elements \
  --calibration results/b0_calibration/b0_calibration.json
~~~

输出 `known_element_hits.tsv` 和 `known_element_summary.tsv`。

阈值选取规则与边界：

- 不给 `--calibration` 时，只报告**零错配的完美匹配**；这是保守默认，不是"校准过的"阈值；
- 未出现在校准记录中的长度不会套用其他长度的阈值（窗口数量不同，套用不安全），同样退回完美匹配规则；
- 评分尺度是离散的，可达的假阳性率是跳变的，因此记录会同时给出**目标值**和**实际达成值**；
- 若某长度即使取完美匹配阈值也达不到目标假阳性率，记录会明确写出
  `target_met=false` 与 `verdict`，**此时该数据集不得用于声明"已知元件恢复"**。小样本合成 demo 就属于这种情况。

`p_value_proxy` 只是基于 PWM 分数的排序代理，不是 FIMO 的正式 p-value/q-value；正式统计要等 MEME Suite/FIMO 接入后再报告。

当前默认过滤规则：序列统一为大写 DNA 字母，`U` 转为 `T`；含非法字符、空序列、缺少 ID/物种/数据源、或 `N` 比例超过 `max_n_fraction` 的记录不进入清洗表；重复 ID 和完全重复序列只保留第一条。被过滤和去重的数量必须结合 `quality_report.json` 解释。

## 后续命令约定

~~~bash

~~~

运行后必须输出配置快照、输入文件哈希、随机种子、软件版本、日志和结果文件路径。
