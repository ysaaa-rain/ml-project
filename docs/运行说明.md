# 运行说明

当前仓库已经提供两层可运行入口：

1. 数据准备层：清洗、去重、分组、EDA 和来源追踪；
2. 大模型主线层：冻结 DNA 模型 embedding、聚类、近邻、PCA 和遮挡窗口解释。

PWM/MEME/FIMO 是小型解释基线，不是项目主线。

## 1. 基础环境

~~~bash
python -m pip install -r requirements.txt
python -m experiments.preflight --output tmp/preflight_mainline.json
~~~

`preflight` 分别报告：

- `embedding_runtime.ready`：PyTorch 与 Transformers 是否已安装；
- `meme_suite.ready`：传统小基线工具是否齐全；
- Python、平台和关键包版本。

`embedding_runtime.ready=true` 只表示依赖可导入，不代表模型权重、固定 revision、许可证、设备或真实数据已经审计完成。

## 2. 数据准备

输入 CSV/TSV 至少包含：

~~~text
sequence_id  species  source_dataset  sequence
~~~

推荐同时提供 `sigma_factor_type`、`evidence_level`、TSS/窗口信息。运行 demo：

~~~bash
python -m experiments.run_m1 --config configs/m1_demo.yaml
~~~

主要输出：

- `promoters_clean.tsv`：大模型和传统基线共用的清洗表；
- `promoters_clean.fasta`：传统小基线需要时使用；
- `background_shuffled.fasta`：组成保持的负对照；
- `quality_report.json`：过滤、长度、GC 和分组统计；
- `group_summary.tsv`、`position_composition.tsv` 和 EDA 图；
- `m1_manifest.json`：输入/配置哈希与环境快照。

真实数据示例：

~~~bash
python -m preprocessing.build_dataset \
  --input data/raw/promoters_metadata.tsv \
  --output-dir data/processed/m1 \
  --validation-source dbtbs \
  --background-replicates 10 \
  --seed 20260913
~~~

必须先完成来源审计、TSS 方向统一和近同源簇隔离，再形成正式 embedding 结论。

## 3. L0-L2 大模型主线

真实配置模板：`configs/l0_embedding.example.yaml`。当前优先模型为 50M 多物种 Nucleotide Transformer，模型 ID 和 revision 已写入配置；运行前仍需核验许可证与本机资源。

~~~bash
python -m experiments.run_embedding --config configs/l0_embedding.example.yaml
~~~

主线输出：

- `sequence_embeddings.npy`：冻结 sequence embedding；
- `embedding_index.tsv`：向量行与序列、物种、来源、σ 因子的对应关系；
- `embedding_clusters.tsv`：聚类和 PCA 坐标；
- `nearest_neighbors.tsv`：余弦最近邻；
- `occlusion_windows.tsv`：滑动窗口遮挡的重要性；
- `embedding_summary.json`：维度、silhouette 和标签对齐诊断；
- `embedding_manifest.json`：模型 ID/revision、配置/输入哈希及全部产物索引。

### 真实模型 demo smoke

~~~bash
python -m experiments.run_m1 --config configs/m1_demo.yaml
python -m experiments.run_embedding --config configs/l0_embedding_hf_demo.yaml
~~~

这里使用真实预训练权重，但输入仍是 6 条 demo。成功只能证明模型接口可运行，不得据此报告生物学结论。

### 无权重时的代码链路 smoke

~~~bash
python -m experiments.run_embedding --config configs/l0_embedding_demo.yaml
~~~

该配置使用 `hash-smoke`。代码强制要求 `allow_test_backend: true`，产物写明 `evidence_level=smoke_only`。这些向量不是大模型 embedding，也不能进入正式结果。

## 4. 模型后端约束

`models/dna_embedding.py` 支持：

- `huggingface`：真实 DNA 预训练模型，必须固定 revision；
- `hash-smoke`：仅供自动测试和无权重时检查文件链路。

真实后端默认冻结参数，支持 mean/CLS pooling、批处理、截断和 CPU/CUDA 自动选择。对于需要 `trust_remote_code=true` 的模型，必须固定 revision 并在实验记录中写明原因。

## 5. 分析与证据边界

- PCA/UMAP 只作展示；主要报告聚类稳定性、silhouette、kNN 一致性和跨来源复现；
- σ 因子、物种和数据源标签用于诊断，不把项目改成分类任务；
- 遮挡分析用 embedding 变化定位局部区域，不把 attention 直接等同于生物学解释；
- discovery 上确定参数，validation 上只复核；
- demo、hash-smoke、真实模型 smoke 和真实数据实验必须分目录保存并分开表述。

## 6. 传统小型解释基线

B0 已知元件 PWM：

~~~bash
python -m experiments.known_element_scan \
  --input data/processed/m1/promoters_clean.tsv \
  --output-dir results/b0_known_elements \
  --min-score 2.0
~~~

`p_value_proxy` 只用于排序。后续最多增加一套 MEME/STREME + FIMO，对大模型重要窗口做解释，不扩展为多套传统算法主线。

## 7. 验证命令

~~~bash
python -m pytest -q
git diff --check
~~~

每次正式运行必须记录输入 SHA256、配置 SHA256、模型 revision、软件版本、随机种子、设备、日志和输出路径。
