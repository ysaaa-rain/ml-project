## 1. 当前数据角色

- 主数据：TJU Pan / PromLoop 六物种 `reg_and_gen/Datasets`。

- RegulonDB GFF3 `Sequence` 已是转录方向，不得再次按 genomic strand 翻转。
- DBTBS 只对网页证据完整且通过一致性校验的记录恢复 TSS/strand。

## 2. 当前允许执行的数据命令

### RegulonDB 原始 GFF3 适配

使用 `preprocessing/source_adapters.py` 的 `adapt_regulondb_gff3` 路径。其语义是：直接保留 GFF3 `Sequence` 的转录方向；strand 仅作 provenance。

正式使用修复后的 `data/processed/g0_rebuild_20261004/`，不要恢复已删除的 `data/processed/m1_regulondb_tss_20260930/`。

### DBTBS 坐标恢复

在项目根目录运行：

```bash
python -B -m preprocessing.recover_dbtbs_coordinates \
  --pages-dir data/raw/dbtbs_v4.1_20261005/pages \
  --metadata-output data/interim/dbtbs_metadata_recovered_20261005.tsv \
  --report-output data/interim/dbtbs_coordinate_recovery_20261005.json
```

该命令只重解析已经冻结的 DBTBS 4.1 HTML，不下载新数据，不运行 motif。输出需要重点检查：

- `coordinate_status=recovered_from_dbtbs` 数量；
- `coordinate_issue` 各原因数量；
- `location_nd_or_missing` 数量；
- mixed/missing gene direction 页面；
- relative span、absolute span 与 sequence length 是否一致。

DBTBS 官方坐标参考写作 `NC_000964`。在从当前 NCBI `NC_000964.3` 重建新的 `[-60,+20]` 窗口前，先验证页面序列与该版本绝对坐标相符。
