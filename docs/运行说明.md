# 运行说明

当前仓库有两层入口：

1. 数据准备层：清洗、去重、TSS 窗口、近同源隔离、背景和 EDA；
2. 大模型主线层：冻结 DNA 模型 embedding、聚类、近邻、PCA 和遮挡窗口解释。

PWM/MEME/FIMO 是小型解释基线，不是项目主线。

## 1. 安装与预检

~~~bash
python -m pip install -r requirements.txt
python -m experiments.preflight --output tmp/preflight_mainline.json
~~~

\`preflight\` 会记录 Python、PyTorch、Transformers、Accelerate 和 MEME Suite 状态：

- \`embedding_runtime.ready=true\` 只表示 Python 依赖可以导入；
- 真实模型还必须核对固定 revision、许可证、下载状态、设备和数据来源；
- MEME Suite 未安装时，不能把 B0 或 Python 输出标记为正式 motif 实验。

## 2. 数据准备

### 2.0.0 下载老师要求的真实来源

老师原文点名的来源包括 RegulonDB、DBTBS 和各物种基因组注释。本仓库已提供两个官方来源的下载入口，下载后保存在本地 `data/raw/`，不会把大文件提交到 Git：

~~~bash
python -m preprocessing.download_regulondb
python -m preprocessing.download_dbtbs
~~~

第一条下载 RegulonDB 官方 raw media 中的 `PromoterSet.gff3` 和 E. coli K-12 genome FASTA；第二条固定 DBTBS 官方 `/ver4/` release 4.1 的 promoter index，并抓取详情页。下载报告会记录访问日期、URL、文件大小、页面数量和 SHA256。首次正式下载后，应把报告与[真实数据下载记录](数据下载记录_20260916.md)逐项核对。

本次已实际生成的适配与构建命令为：

~~~bash
python -m preprocessing.source_adapters --input data/raw/regulondb_promoters_20260916.gff3 --output data/interim/regulondb_metadata_20260916.tsv --source-id regulondb --default-species 'Escherichia coli'
python -m preprocessing.assemble_metadata --input data/interim/regulondb_metadata_20260916.tsv --input data/interim/dbtbs_metadata_20260916.tsv --output data/interim/promoters_metadata_20260916.tsv --report data/interim/assembly_report_20260916.json
python -m experiments.run_m1 --config configs/m1_real_native_20260916.yaml
~~~

当前配置是“来源原生窗口”第一轮构建：因为 DBTBS 页面没有足够证据提供统一 TSS 和链方向，所以不猜测坐标，也不把这批结果写成已完成 TSS 对齐实验。

### 2.0 外部来源字段适配

真实数据库的列名不一定和项目内部名称一致。先用适配器统一字段，再进入清洗；适配器只做列名映射和显式来源登记，不会猜测缺失的 sigma、TSS 或链方向。缺少必填字段会直接报错，缺少可选字段会留空并写入适配报告。

例如，输入表包含 `promoter_id`、`organism`、`DNA sequence` 等常见列名时：

~~~bash
python -m preprocessing.source_adapters \
  --input data/raw/source_table.tsv \
  --output data/interim/regulondb_metadata.tsv \
  --source-id regulondb \
  --report data/interim/regulondb_adapter_report.json
~~~

如果来源文件没有物种列，只能由操作者显式提供来源审计后确认的值：

~~~bash
python -m preprocessing.source_adapters \
  --input data/raw/dbtbs_table.tsv \
  --output data/interim/dbtbs_metadata.tsv \
  --source-id dbtbs \
  --default-species "Bacillus subtilis"
~~~

执行前要先把真实文件名、版本、下载日期、许可和 SHA256 记录在来源审计文档中。适配后的 TSV 才能交给下面的 `build_dataset` 或 `run_m1`。

多个来源适配完成后，先合并并生成输入文件哈希清单：

~~~bash
python -m preprocessing.assemble_metadata \
  --input data/interim/regulondb_metadata_20260916.tsv \
  --input data/interim/dbtbs_metadata_20260916.tsv \
  --output data/interim/promoters_metadata_20260916.tsv \
  --report data/interim/assembly_report_20260916.json
~~~

合并器要求 `sequence_id` 在所有来源中全局唯一；发现冲突会停止，不会自动改名。

输入 CSV/TSV 至少包含：

~~~text
sequence_id  species  source_dataset  sequence
~~~

推荐同时提供 \`sigma_factor_type\`、\`evidence_level\`、\`tss_position\` 和 \`strand\`。运行最小 demo：

~~~bash
python -m experiments.run_m1 --config configs/m1_demo.yaml
~~~

主要输出：

- \`promoters_clean.tsv\`：大模型和传统基线共用的清洗表；
- \`promoters_clean.fasta\`：小型传统基线需要时使用；
- \`background_shuffled.fasta\`：N0 单核苷酸组成保持背景；
- \`background_dinucleotide.fasta\`：N1 二核苷酸组成保持背景；
- \`quality_report.json\`：输入/输出数量、过滤原因、长度、GC、窗口和同源信息；
- \`group_summary.tsv\`、\`position_composition.tsv\` 和 EDA 图；
- \`m1_manifest.json\`：输入/配置哈希与环境快照。

正式数据运行前必须完成来源、版本、许可、TSS 方向、sigma 标签和原文件 SHA256 审计。本次真实来源的实际记录见[数据下载记录](数据下载记录_20260916.md)；统一 TSS 窗口仍是下一步 Gate A，不因已有原生窗口输出而跳过。

### 2.1 TSS 窗口与链方向

motif 位置和大模型局部窗口只有在同一坐标系中才可比较。启用窗口后，每条记录按 \`[-upstream, +downstream]\` 截取；负链序列反向互补，使“上游”在两条链上含义一致：

~~~bash
python -m preprocessing.build_dataset \
  --input data/raw/promoters_metadata.tsv \
  --output-dir data/processed/m1 \
  --validation-source dbtbs \
  --tss-window 60 20 \
  --homology-clustering
~~~

或在配置中写：

~~~yaml
tss_window:
  upstream: 60
  downstream: 20
tss_column: tss_position
strand_column: strand
homology_clustering: true
identity_threshold: 0.90
kmer_size: 15
~~~

缺少 TSS/链方向或窗口越界的记录会按原因计数后丢弃，不静默截断或平移。输出会增加 \`window_start_1based\`、\`window_end_1based\`、\`tss_offset_in_window\` 和 \`window_strand\`。

### 2.2 近同源聚类与泄漏控制

仅按 \`source_dataset\` 划分可能让近同源序列落在 discovery 和 validation 两侧。启用后，程序先用 k-mer 草图预筛，再按序列相似性聚成簇，并以整簇为单位分配 split。正式报告要求 \`homology_split.leakage_violations_after=0\`。

### 2.3 负对照

N0 只保持单碱基组成；N1 同时保持单、二核苷酸组成，后者是更严格对照。两者使用同一随机种子，区别只来自打乱算法。正式显著性不能只依赖 N0。

## 3. L0-L2 大模型主线

正式配置：\`configs/l0_embedding.example.yaml\`。第一轮模型已经固定为：

~~~text
InstaDeepAI/nucleotide-transformer-v2-50m-multi-species
revision: f1ff02bacb08d292ee9c3e227356d692055ac50d
pooling: mean
~~~

运行：

~~~bash
python -m experiments.run_embedding --config configs/l0_embedding.example.yaml
~~~

输出：

- \`sequence_embeddings.npy\`：冻结 sequence embedding；
- \`embedding_index.tsv\`：向量行与序列元数据的对应关系；
- \`embedding_clusters.tsv\`：聚类标签和 PCA 坐标；
- \`nearest_neighbors.tsv\`：余弦最近邻；
- \`occlusion_windows.tsv\`：滑动窗口遮挡重要度；
- \`embedding_summary.json\`：维度、silhouette 和标签对齐诊断；
- \`embedding_manifest.json\`：模型 ID/revision、配置/输入/输出哈希及产物索引。

真实模型 demo：

~~~bash
python -m experiments.run_m1 --config configs/m1_demo.yaml
python -m experiments.run_embedding --config configs/l0_embedding_hf_demo.yaml
~~~

该 demo 已成功生成 6 条序列的 \`6×512\` embedding 和 8 个窗口，但输入仍是人为构造的 demo，不能作为生物学结果。

没有模型权重时的代码链路 smoke：

~~~bash
python -m experiments.run_embedding --config configs/l0_embedding_demo.yaml
~~~

该配置使用 \`hash-smoke\`，必须显式写 \`allow_test_backend: true\`，产物标记为 \`smoke_only\`。这些向量不能进入正式结果。

## 4. 模型后端约束

\`models/dna_embedding.py\` 支持：

- \`huggingface\`：真实 DNA 预训练模型，必须固定 revision；
- \`hash-smoke\`：只供测试和无权重时检查文件链路。

真实后端默认冻结参数，支持 mean/CLS pooling、批处理、截断和 CPU/CUDA 自动选择。需要 \`trust_remote_code=true\` 时，必须固定 revision 并在实验记录中写明原因。

## 5. 分析与证据边界

- PCA/UMAP 只作展示；主结果看聚类稳定性、kNN 一致性和跨来源复现；
- sigma、物种和数据源标签只用于诊断，不把项目改成分类任务；
- 遮挡分析用 embedding 变化定位局部区域，不把 attention 直接等同于生物学解释；
- discovery 上确定参数，validation 上只复核；
- demo、hash-smoke、真实模型 smoke 和真实数据实验必须分目录保存、分开表述。

## 6. 传统小型解释基线

B0 扫描 \`TTGACA\`（-35 box）和 \`TATAAT\`（-10 box）。B0 已支持按长度校准阈值：

~~~bash
python -m experiments.calibrate_b0 \
  --input data/processed/m1/promoters_clean.tsv \
  --output-dir results/b0_calibration \
  --shuffle-method dinucleotide \
  --background-per-length 5000
~~~

然后运行：

~~~bash
python -m experiments.known_element_scan \
  --input data/processed/m1/promoters_clean.tsv \
  --output-dir results/b0_known_elements \
  --calibration results/b0_calibration/b0_calibration.json
~~~

没有校准记录时，B0 只报告零错配完美匹配；\`p_value_proxy\` 只是排序代理，不是 FIMO 正式 p-value/q-value。课程要求的最小 motif 线还需要选择一套可运行工具，在全序列和 sigma 分组上发现 motif，再用 FIMO 定位并完成间距/排列统计。它保持为一套紧凑验证线，不扩展为传统算法主线，也不能只对大模型候选窗口运行而跳过全序列/分组输入。
