原生效日期：2026-10-04。**2026-10-05 按用户最新决定整体修订；本版本取代旧版的数据角色与执行顺序。** 旧版本仅可从 Git 历史追溯，不再作为当前全局规范。

## 1. 当前最高优先级决定

PR01-02 当前固定数据架构：

> **TJU Pan / PromLoop 六物种为主数据；RegulonDB / DBTBS 主要负责 sigma annotation、机制解释和独立来源验证。**

在数据审计、清洗、冻结和输入验收完成前，不运行新的正式 MEME/FIMO。embedding / Nucleotide Transformer / clustering / occlusion / SAE 等路线后置为探索项。

课程 RQ1–RQ3 和必做实验仍需逐项交付；任何历史结果只有在其输入、划分和数据处理仍符合当前规范时才可继续作为正式证据。

## 2. 三类数据的角色

### 2.1 TJU Pan / PromLoop 六物种：主序列数据

- 云盘 `reg_and_gen/Datasets` 已与 `KevinHZS/PromLoop` 固定提交对应 30 个 CSV 逐文件 SHA256 核验一致。
- 采用 PromLoop 发布的数据定义：81 bp、相对 TSS `[-60,+20]` 的标准化 promoter 序列。
- 不重新从基因组截取 TJU 序列；不依据 CSV 中缺失的 strand 再做 reverse-complement。
- 项目层面视发布序列为已经完成上游 TSS/方向标准化；不得虚构“逐条独立核验了所有原始 strand”的证据。
- TJU 缺逐条 sigma factor 标签，因此不承担 RQ2 的主 sigma-specific 证据。
- `Dataset.csv`、`positive_samples.csv`、train/dev/test 必须重新验收标签、ID、exact/RC 重复和近同源关系；原始 CSV 不静默修改。
- 正式 motif discovery 以通过验收的 TJU promoter positive 为主输入。最新决定（2026-10-08）：TJU label=0 是正式 STREME 主背景，但不宣称其无组成偏差；同一 discovery positive 另与已生成的 dinucleotide-shuffled 背景运行 STREME 稳健性对照。两次实验不得混合负集。
- 六物种原始 negative（`discovery.natural_control.fasta`）及二核苷酸保持随机对照（`discovery.dinucleotide_null.fasta`）均已生成并作为两套预注册对照使用：前者为主、后者为稳健性；不准备 GC-matched 数据、不按 GC 分层。GC 组成差异作为解释限制记录，不能据此宣称排除了所有组成混杂。正式输入/随机种子/参数/哈希在运行前冻结。

### 2.2 RegulonDB E. coli：RQ2 主 sigma 数据与独立来源验证

- 官方 GFF3 `Sequence` 已按转录方向提供；genomic strand 是 provenance，**不得再次按负链 reverse-complement**。
- TSS、strand、genomic coordinate、evidence、source record ID 均从原始字段保留；缺失/歧义不猜。
- sequence 去重不能丢失 promoter↔sigma 多对多关系。序列表与 sigma association 表分离或用等价的多标签结构保存。
- 正式 split 按同源簇隔离，不使用旧记录级随机 80/20 作为当前验证入口。
- 旧 3,807 条错误方向输入及其直接派生 MEME/Tomtom/FIMO/spacing/holdout 结果已退出当前正式结果树。
- 修复后的 `data/processed/g0_rebuild_20261004/` 可继续作为 RegulonDB 辅助机制数据基础，但其角色不再是整个项目的主物种发现入口。

### 2.3 DBTBS 4.1 B. subtilis：sigma/坐标/文献注释

DBTBS 官方页面提供 Genes `Direction`、promoter `Location`、`Absolute position`、cis-element sequence、sigma factor 和实验 evidence。官方 terms 定义 `Location` 是相对 transcription start site 的位置；`Absolute position` 按 NCBI accession `NC_000964` 重算；网页粗体表示 TSS。

因此旧 parser 将 `tss_position/strand` 全部留空属于解析不足，不代表 DBTBS 本身没有这些信息。

当前恢复规则：

1. 从冻结的 release 4.1 原始 HTML 读取 gene Direction。
2. 解析 promoter Location 和 Absolute position。
3. relative span、absolute span、实际序列长度三者必须一致。
4. Location 必须跨越 TSS（`start <= 0 < end`）。
5. 只有 Direction 唯一且上述校验全部通过，才标记 `coordinate_status=recovered_from_dbtbs`。
6. `Location=ND`、坐标不可解析、长度不一致、方向混合/缺失全部保留为 unresolved；不得由 motif 或模型反推 TSS。
7. DBTBS 官方只写 accession `NC_000964`。当前 NCBI reference 为 `NC_000964.3`，在用其重建新 81 bp 窗口前必须先用 DBTBS 页面序列/坐标验证版本兼容，不能静默替换版本。

实现入口：`preprocessing/recover_dbtbs_coordinates.py`。

## 3. RQ1 / RQ2 / RQ3 数据安排

### RQ1：启动子 motif 与已知元件

主发现：TJU 六物种清洗后的 promoter positives。

分析链：MEME/STREME/DREME → FIMO → motif position / spacing / arrangement → 与可靠已知 -10/-35/UP 等参考比较。

RegulonDB/DBTBS 用于提供更完整的机制注释和已知 sigma 元件证据，但不替代 TJU 六物种主发现。

### RQ2：sigma factor 类型比较

主数据：RegulonDB E. coli 的可靠 sigma association。

补充：DBTBS 中坐标/证据可恢复且样本量足够的 sigma groups。

TJU 不进行无标签的 sigma 推断后再把推断结果当真值。

### RQ3：稳定性与泛化

必须分开报告：

1. **跨物种**：例如 TJU E. coli vs TJU B. subtilis；
2. **同来源 holdout**：同一发布体系内按同源簇隔离的 discovery/validation；
3. **同物种跨数据集**：TJU E. coli ↔ RegulonDB E. coli；TJU B. subtilis ↔ DBTBS B. subtilis；
4. **跨物种 + 跨数据集**：例如 RegulonDB E. coli ↔ DBTBS B. subtilis。

同一个物种、不同独立数据来源可以作为 cross-dataset validation，但前提是先排除 exact、reverse-complement 和冻结阈值下的近同源重叠。来源不同不自动等于样本独立。

## 4. 统一数据处理流水线

```text
raw snapshot
→ provenance/version/hash audit
→ source-specific parsing
→ orientation/TSS normalization
→ sequence/label QC
→ exact + reverse-complement duplicate audit
→ near-homology clustering
→ sigma normalization / many-to-many associations
→ discovery/holdout/cross-dataset isolation
→ background construction
→ FASTA + metadata + exclusion table + SHA256 manifest
→ 数据方案验收
→ 正式 motif discovery / FIMO
```

### 4.1 原始数据

- 原始下载快照只读保存，不因解析错误删除。
- 每个来源记录 URL/版本/访问日期/SHA256。
- 派生表不得覆盖原始文件。

### 4.2 序列与标签

- 正式主 discovery 使用确认的 promoter positive。
- 非 A/C/G/T、长度异常、标签冲突、无法解释的重复记录进入 exclusion/issue 表，不静默修正。
- 完全重复与 reverse-complement 重复必须审计；统计同时报告记录数与唯一序列数。
- 高相似序列按冻结算法/阈值聚类，整个 cluster 只能进入一个 split。

### 4.3 TSS 与方向

- TJU：采用 PromLoop 已发布 81 bp `[-60,+20]` 标准化，不二次处理方向。
- RegulonDB：采用原始 GFF3 转录方向 Sequence，禁止按 genomic strand 二次翻转。
- DBTBS：只对有显式证据且通过一致性校验的记录恢复 TSS/strand；必要时再从验证过版本的 B. subtilis 168 reference genome 截取统一 81 bp。

### 4.4 sigma

保存 `sigma_raw` 与 `sigma_normalized`；同一 promoter 多 sigma 必须全部保留。unknown/缺失不猜。正式组最低样本量在分析计划中预先固定；小组不足时只做描述或合并到有生物学依据的 family，不为了显著性任意合并。

### 4.5 provenance

每个最终记录至少可追踪：`source_dataset, source_version, source_record_id, species, sequence, sequence_hash, label, tss definition, strand/orientation evidence, genomic coordinates (if available), sigma_raw, sigma_normalized, cluster_id, split, exclusion_reason`。

每次生成 final FASTA 同时生成 metadata TSV、exclusion TSV、manifest JSON；manifest 包含代码 Git SHA、命令、参数、输入输出 SHA256 和记录计数。

## 6. 正式实验启动条件

开始新的正式 MEME/STREME/DREME/FIMO 前必须同时满足：

1. TJU 六物种主正样本入口冻结；
2. Dataset/positive_samples/train/dev/test 的关系及标签冲突处理写清；
3. exact/RC/近同源泄漏审计完成；
4. 主背景和敏感性背景准备完成；
5. RegulonDB 修复数据与 sigma association 验收；
6. DBTBS 可恢复/不可恢复记录形成明确清单；
7. RQ1/RQ2/RQ3 各自使用的数据集与 split manifest 固定；
8. 所有 final FASTA/metadata/exclusion/manifest 具备 SHA256。

满足以上条件后，再从 TJU 主数据的第一份已验收 discovery positive FASTA 开始正式 motif discovery。不要先跑正式 MEME 再回头补数据定义。
