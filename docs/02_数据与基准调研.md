## 1. 当前使用的数据

### 1.1 TJU Pan 主数据

老师通过天津大学云盘提供 resources/promoter。本机下载了其中与启动子任务有关的 reg_and_gen 与 strenth 目录；原始文件在 data/raw/tju_pan_promoter/，被 Git 忽略。校验清单 SHA256SUMS.txt 中的 59 个文件均已验证。

reg_and_gen/Datasets 有六个物种、每个物种五个 CSV。字段为 seq_id, seq_type, seq, label，其中 label=1 是正类 promoter，label=0 是负类对照。上游 PromLoop README 描述序列长度为 81 bp、相对 TSS 的 −60 到 +20 bp，并声称按 90% identity 去冗余后再拆分。该说明没有在云盘 CSV 中提供逐记录来源、σ、基因组坐标或链方向；负链是否已统一到转录方向仍待验证。

### 1.2 其他来源

- **RegulonDB E. coli K-12：** 已有 3,807 条 TSS 对齐 81 bp 序列和六种 σ 标签；用于 σ 组别实验、以及与 TJU Pan E. coli 去重后的来源比较。RegulonDB 与 TJU Pan E. coli 存在数百条相同或反向互补序列，故比较前必须做去重和近同源筛除。
- **DBTBS release 4.1 B. subtilis：** 可选验证数据。已有记录的 TSS/链方向字段需要复查，不用于无证据的 TSS 坐标分析。
- **strenth 候选：** 包含 E. coli、yeast、合成启动子和若干派生数组等不同资料。只有细菌数据的强度含义、单位、实验条件和 sequence mapping 审计通过后，才能开展实验 5。不得把该目录里的每个文件都当作独立样本。

## 2. 跨数据集设计

六物种 TJU Pan 数据适合做跨物种对照，但属于同一个数据发布体系。独立来源比较以 TJU Pan E. coli 和 RegulonDB E. coli 为首选；先去除精确同向、反向互补匹配，再用固定 identity/coverage 阈值排除近同源序列。重复样本数、筛除数、剩余样本数和验证规则写入 manifest 后再运行比较。

每个来源独立保存元数据、序列和处理记录，不把不同窗口定义、标签和证据水平合并成一张“同质”表。

## 3. 数据质量和复现

## 4. 常见可比指标

| 分析问题 | 建议报告 |
| --- | --- |
| motif 是否显著 | MEME/STREME E-value/q-value、对照序列富集、结果重采样稳定性 |
| 是否接近已知元件 | Tomtom 对齐和 FIMO 位点重叠，分开报告相似度与位置 |
| 出现在哪些启动子 | FIMO 唯一序列覆盖率、按组命中比例、p/q 阈值 |
| 位置是否集中 | 经过方向核验的 TSS-relative 分布、分位数和置信区间 |
| 两 motif 的空间组织 | 有方向定义的间距、排列、共现率和对照差异 |
| 能否跨来源重现 | 固定同源排除规则、矩阵相似度、来源内出现率及筛除前后样本数 |

所有阈值在正式运行前固定，结果同时报告效应大小和样本量。只有同一个扫描/统计设计中的量才直接比较；不同软件或不同背景设置的 E-value 不视为可互换分数。
